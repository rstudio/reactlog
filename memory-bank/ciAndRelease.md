# CI, website, and release

All CI lives in one workflow file that calls three shared jobs from
[rstudio/shiny-workflows](https://github.com/rstudio/shiny-workflows) at tag `@v1`.
This repo only adds one hook script, `.github/shiny-workflows/website.R`.
For how the R and JS halves fit together, see [architecture.md](architecture.md).
For the Node/webpack toolchain, see [jsBuild.md](jsBuild.md).

Key files:

| File | Role |
| --- | --- |
| `.github/workflows/R-CMD-check.yaml` | The only workflow ("Package checks"). Calls `website`, `routine`, `R-CMD-check` from shiny-workflows `@v1` |
| `.github/shiny-workflows/website.R` | Hook run by the `website` job before pkgdown builds. Copies the demo and readme gifs into `pkgdown/assets/` |
| `pkgdown/_pkgdown.yml` | pkgdown config: site URL, docsearch, `development: mode: auto` |
| `pkgdown/favicon/` | Site favicons |
| `pkgdown/.gitignore` | Ignores `assets` (it is generated by `website.R`) |
| `DESCRIPTION` | Package version (`1.1.1.9000` = dev after 1.1.1), `Config/roxygen2/version` |
| `NEWS.md` | Changelog. Top heading is `# reactlog (development)` |
| `cran-comments.md` | Notes sent with the last CRAN submission (1.1.1, 2022) |
| `revdep/` | Saved `revdepcheck` results from the 1.1.1 release |
| `scripts/rhub.R` | Old helper that sends a build to R-hub CRAN platforms |
| `.Rbuildignore` | Keeps JS sources, site files, scripts, agent docs out of the CRAN tarball |
| `.lintr` | lintr config used by `routine` and the pre-commit hook |
| `vignettes/reactlog.Rmd`, `vignettes/images/` | The one vignette and its committed images |

## Triggers

`.github/workflows/R-CMD-check.yaml` runs on:

- `push` to `main` or `rc-**` branches,
- `pull_request` into `main`,
- `workflow_dispatch`. There is no cron schedule. It was replaced by
  `workflow_dispatch` in [rstudio/reactlog#99](https://github.com/rstudio/reactlog/issues/99)
  so that [rstudio/shinycoreci](https://github.com/rstudio/shinycoreci) can start runs remotely.

All three jobs run on every trigger. They have no inputs set, so they use the
shiny-workflows defaults.

## `website` job (`website.yaml`)

1. Installs R, pandoc 3.x, the package deps, `pkgdown` and `testthat`.
2. Runs the local hook (`run-local-script` sources `.github/shiny-workflows/website.R` if it exists).
3. On `push` and `workflow_dispatch` it deploys with
   `pkgdown::deploy_to_branch(clean = TRUE)` to `gh-pages`. On `pull_request`
   it only builds: `pkgdown::build_site()`, then fails if
   `pkgdown::build_reference_index()` gives any warning. So every exported
   topic in `man/` must be reachable from the reference index.

`development: mode: auto` in `pkgdown/_pkgdown.yml` means a `.9000` version
builds into the `dev/` sub-site, and a release version builds the main site.

### How the demo and readme gifs reach the site

pkgdown 2.x copies only `pkgdown/assets/` to the site root. `website.R`:

- copies `readme-images/` to `pkgdown/assets/readme-images/`,
- copies `inst/reactlog/` to `pkgdown/assets/` and renames it to `demo`.

So `https://rstudio.github.io/reactlog/demo/reactlog.html` is the committed
JS bundle plus `defaultLog.js`, and `README.md` loads its gifs from
`http://rstudio.github.io/reactlog/readme-images/*.gif`. Each `file.copy()` is
wrapped in `stopifnot()`, so a missing folder fails the job. This was broken
for months because the script used to copy into `pkgdown/` (old
`template: assets:` setting); fixed in
[rstudio/reactlog#119](https://github.com/rstudio/reactlog/issues/119).

To test locally: `Rscript .github/shiny-workflows/website.R`, then
`pkgdown::build_site()`, and check `docs/demo/reactlog.html` and
`docs/readme-images/`.

## `routine` job (`routine.yaml`)

Runs on R release with `devtools`, `roxygen2`, `lintr`, `usethis` and friends.
It makes commits, and on a same-repo PR it pushes them back to the PR branch
(`r-lib/actions/pr-push`). On `push` it fails if it made any commit
("GHA should not auto-push"). On a fork PR it also fails if it made a commit;
you must run the steps yourself.

Steps that may auto-commit, in order:

| Step | What it changes here |
| --- | --- |
| `urlchecker::url_update()` | URLs in the package. Only on `rc-v*` branches |
| Set version from branch | On `rc-vX.Y.Z`, sets `DESCRIPTION` `Version` and adds a `NEWS.md` heading |
| `usethis::use_tidy_description()` | Reorders and reformats `DESCRIPTION` |
| `devtools::document()` | `DESCRIPTION`, `NAMESPACE`, `man/` |
| `oxipng` | Lossless PNG shrink on `man/figures/*.png` and `vignettes/*.png`. Git pathspec `*` also matches `/`, so this hits all 22 PNGs under `vignettes/images/` |
| `npm ci` + `npm run build` | Uses Node `current`. `package.json` has a `build` script, so this runs (`npm ci` also runs `postinstall`, which builds). `build` runs `lint-all` (eslint `--fix` + prettier on `srcjs/`) then webpack. Commits changes under `inst/` and `srcjs/` plus `package-lock.json` |

There is no `README.Rmd`, `codecov.yml`, or `# @staticimports`, so those steps skip.
After pushing, it runs `devtools::lint()` (because `.lintr` exists) and fails on
any lint. `.lintr` sets line length 100 and excludes
`inst/examples/03_reactivity/app.R`.

## `R-CMD-check` job (`R-CMD-check.yaml`)

Builds a matrix from the R versions on the runner image. With no `src/` folder
this repo gets: macOS release, Windows release, Ubuntu devel, release and
oldrel-1 to oldrel-4, plus a `check-depends-only` job
(`_R_CHECK_DEPENDS_ONLY_=true`, so `Suggests` such as shiny are not
installed). Check args are `--no-manual --as-cran`; build args add
`--compact-vignettes=gs+qpdf`. It fails on warnings (`error-on: "warning"`),
not notes. No local `check` hook exists.

Because of the depends-only job, examples, tests and the vignette must not
assume `shiny` is installed. The module example in `R/shinyModule.R` is wrapped
in `if (requireNamespace("shiny", quietly = TRUE))` for this reason.

## Automated remediation PRs from shinycoreci

shinycoreci dispatches this workflow on `main`. When it fails, an issue is opened
and the `posit-shiny-automation` app opens a "fix(ci): remediate reactlog
package checks on main" PR that closes it. The PR body links the failed run.
Recent ones:

- [rstudio/reactlog#114](https://github.com/rstudio/reactlog/issues/114):
  `R/shinyModule.R` example made safe without shiny (regenerated
  `man/reactlog_module.Rd`), `error = function(e)` fix, `DESCRIPTION` tidy.
- [rstudio/reactlog#118](https://github.com/rstudio/reactlog/issues/118):
  tidy `DESCRIPTION` (roxygen 8 `Config/roxygen2/version` replaced
  `RoxygenNote`), lint fixes, `shiny_version_required()` call bug, roxygen link
  target `shiny::reactlogShow`, `NODE_OPTIONS=--openssl-legacy-provider` for
  webpack 4, and `oxipng`-shrunk vignette PNGs.

Read these PRs before "fixing" the same lines again; they show what `routine`
will otherwise keep rewriting.

## Docs: `man/` and the vignette

- `man/*.Rd` and `NAMESPACE` are generated by roxygen (`Roxygen: list(markdown = TRUE)`).
  Edit the `#'` comments in `R/`, then run `devtools::document()`. If you skip
  it, `routine` commits the result for you on a PR.
- `vignettes/reactlog.Rmd` has `echo = FALSE` and runs no package code. Images
  are committed files shown with `knitr::include_graphics()`: the
  reactivity diagrams in `vignettes/images/04-reactivity/` (source
  `originals/` is gitignored and not in the repo), UI screenshots in
  `vignettes/images/`, and button icons in `vignettes/images/buttons/`, which
  are copies of `inst/reactlog/reactlogAsset/images/*.svg`. Videos are Vimeo
  iframes. Nothing regenerates these images; replace them by hand.

## Versions and release files

- Dev versions end in `.9000` (`1.1.1.9000` now). Tags are `v1.0.0`, `v1.1.0`,
  `v1.1.1`, each with a GitHub release.
- `R/version.R` is not the package version. It holds `reactlog_upgrade()`,
  which checks the log format version (only `"1"`).
- `NEWS.md` starts with `# reactlog (development)`. CONTRIBUTING asks for a
  NEWS entry per user-facing change.
- `cran-comments.md`, `revdep/*.md` and `scripts/rhub.R` are left over from the
  1.1.1 release and are not run by CI.

### Release steps (from the files above)

1. Branch `rc-vX.Y.Z` and push. `routine` sets the version in `DESCRIPTION`,
   adds the `NEWS.md` heading, and runs `urlchecker::url_update()`; pull its
   commits.
2. Rename `# reactlog (development)` in `NEWS.md` if `routine` added a new heading above it.
3. Make sure the committed JS bundle is current ([jsBuild.md](jsBuild.md)).
4. Run reverse dependency checks (shiny is the only revdep) and refresh `revdep/`.
5. Optionally run `scripts/rhub.R`; check with win-builder.
6. Update `cran-comments.md` (date, environments, results) and submit.
7. After acceptance, tag `vX.Y.Z`, make a GitHub release, and bump
   `DESCRIPTION` to `X.Y.Z.9000` with a new `# reactlog (development)` heading.

## `.Rbuildignore`

Keeps out of the tarball: `srcjs`, `bin`, `node_modules`, JS config files,
`package.json`/`package-lock.json`, `*.js.map`, `inst/log-files`, `inst/gantt`,
`readme-images`, `logo`, `pkgdown`, `revdep`, `scripts`, `.github`,
`cran-comments.md`, `AGENTS.md`, `.agents`, `.claude`, `memory-bank`,
`.context` (Conductor workspace files) and `.git` (a worktree's `.git` is a
file, which R CMD build does not skip on its own). Add new top-level dev files
here.

## Pitfalls

- `R CMD build` packs every file not matched by `.Rbuildignore`, tracked or not.
  In a Conductor worktree this includes `.context/` and the `.git` file. Build
  release tarballs from a clean clone.
- `routine` pushes commits to your PR branch. Pull before pushing again, or you
  will get a non-fast-forward error.
- A `srcjs/` lint problem can turn into a `routine` commit (eslint `--fix`), or
  fail `npm run build`. Node `current` plus webpack 4 needs
  `--openssl-legacy-provider`; keep it in `build-only`.
- Do not move `website.R` output back to `pkgdown/`. pkgdown 2.x ignores it
  and the demo and gifs vanish from the site with no CI error.
- `pkgdown/assets/` is generated and gitignored. Do not commit it.
- PR builds fail on any pkgdown reference index warning. Add new exports to
  roxygen docs and check `pkgdown::build_reference_index()`.
- Keep the `shiny` version in `DESCRIPTION` `Suggests` correct: the depends-only
  job checks without it, and `shiny_version_required()` reads it at runtime.
- `scripts/rhub.R` uses the old rhub v1 API (`rhub::check_for_cran()`,
  `rhub:::build_package()`). rhub 2.x moved to GitHub Actions based checks
  (`rhub::rhub_check()`), so expect to rewrite it.
